# UAT Checklist — ISMS-Lite (ก่อน deploy / MVP 1.0)

รายการทดสอบยอมรับ (User Acceptance Testing) ให้ไล่กดทีละข้อ ✅/❌ ก่อนขึ้น production
เตรียม: มีผู้ใช้อย่างน้อย 1 คน (แนะนำ 2–3 คนเพื่อทดสอบ workflow ข้ามบทบาท)

## 1. Authentication
- [ ] เข้า `/` แล้วกด "เข้าสู่ระบบด้วย Google" → login ด้วย `@maholan.co.th` สำเร็จ
- [ ] ลอง login ด้วย Gmail ทั่วไป → ถูกปฏิเสธ (AccessDenied)
- [ ] เห็นชื่อผู้ใช้ + ปุ่มออกจากระบบบนแถบบน
- [ ] เข้า `/process/y07` ตอนยังไม่ login → เด้งไป `/login`

## 2. สิทธิ์ (RBAC — admin / isms_manager / member)
- [ ] ผู้ใช้ทั่วไป = **member**: ไม่เห็น "⚙ ผู้ตรวจ/อนุมัติ", ไม่เห็นกล่อง default ในหน้ากระบวนการ, ไม่เห็นปุ่มจัดการปฏิทิน/Drive
- [ ] **admin**: เห็น badge ADMIN + ปุ่ม "⚙︎ ตั้งค่าโฟลเดอร์ Drive" + ทุกเมนูจัดการ (โปรโมท `npm run promote-admin -- <email>`)
- [ ] **isms_manager** (ตั้งด้วย `npm run set-role -- <email> isms_manager`):
  - [ ] เห็นเมนู **⚙ ผู้ตรวจ/อนุมัติ** (`/settings/assignees`) + กล่อง default ในหน้ากระบวนการ → ตั้งค่าได้
  - [ ] เห็นปุ่มจัดการ **ปฏิทิน ISO** (ปรับ lead_days / mark done / run reminder / Import)
  - [ ] **ไม่เห็น** ปุ่มตั้งค่าโฟลเดอร์ Drive · **ลบเอกสารร่างไม่ได้** (เป็นสิทธิ์ admin)
  - [ ] member เรียก API `/settings/assignees/bulk` หรือ `/api/calendar/*` ตรง ๆ → ได้ **403**

## 2.1 ตั้งค่าผู้ตรวจ/ผู้อนุมัติเริ่มต้น (`/settings/assignees`)
- [ ] "ใช้กับทุกกระบวนการ" → เลือก reviewer+approver → ยืนยัน → ทั้ง 18 กระบวนการได้ค่าเดียวกัน
- [ ] แก้รายกระบวนการ (ปุ่ม "บันทึก" โผล่เมื่อแก้) → ค่าเฉพาะกระบวนการนั้นเปลี่ยน
- [ ] กด "ส่งตรวจ" เอกสาร → ช่องผู้ตรวจ/ผู้อนุมัติเติม default อัตโนมัติ (ยังแก้รายเอกสารได้)

## 3. เช็คอินเอกสาร (Drive)
- [ ] เข้ากระบวนการใด ๆ → กรอกชื่อ + แนบไฟล์ → "⬆️ เช็คอิน" สำเร็จ
- [ ] เอกสารปรากฏในตาราง สถานะ **ร่าง** v1
- [ ] ไฟล์ขึ้นจริงในโฟลเดอร์ของกระบวนการนั้นใน Shared Drive `ISMS Repository`
- [ ] "อัปเวอร์ชัน" → ได้ v2 (สถานะกลับเป็น ร่าง)

## 4. Workflow (Draft → Review → Approved → Published)
- [ ] ผู้จัดทำกด **ส่งตรวจ** เลือกผู้ตรวจ + ผู้อนุมัติ → สถานะเป็น "รอตรวจ"
- [ ] ผู้ตรวจเห็นงานใน 📥 งานของฉัน → กด **ตรวจผ่าน**
- [ ] ผู้อนุมัติเห็นงาน → กด **อนุมัติ** → สถานะ "อนุมัติแล้ว"
- [ ] ผู้อนุมัติ/admin กด **เผยแพร่** → สถานะ "เผยแพร่"
- [ ] ทดสอบ **ตีกลับ** (ต้องระบุเหตุผล) → กลับเป็น "ตีกลับ" และส่งกลับผู้จัดทำได้

## 5. แจ้งเตือน (in-app + email)
- [ ] แต่ละ transition → 🔔 ขึ้นเลขให้คนที่เกี่ยวข้อง
- [ ] เปิด `/notifications` → เห็นรายการ + เลขกระดิ่งหายหลังเปิด
- [ ] (ถ้าตั้ง Resend) ได้รับอีเมลแจ้งเตือน

## 6. ดาวน์โหลด PDF-only
- [ ] เอกสาร **เผยแพร่** → กด "⬇︎ PDF" ได้ไฟล์ PDF (ไม่ใช่ไฟล์ต้นฉบับ)
- [ ] PDF มีลายน้ำ "CONTROLLED COPY" + บรรทัดล่างระบุผู้ดาวน์โหลด/เวลา
- [ ] เอกสารที่ยังไม่เผยแพร่ → ผู้ที่ไม่เกี่ยวข้องไม่เห็น/ดาวน์โหลดไม่ได้ (403)

## 7. Dashboard + Timeline
- [ ] `/dashboard` แสดงจำนวนเอกสารตามสถานะ + coverage 18 กระบวนการ + งานค้าง
- [ ] คลิกชื่อเอกสาร → หน้า `/documents/[id]` เห็นเวอร์ชัน + **Timeline** ครบทุกเหตุการณ์

## 8. หน้า Landing (สถานะเฉด)
- [ ] กระบวนการที่มีไฟล์ → การ์ดมีเฉดพื้น (สีตาม phase)
- [ ] กระบวนการที่มี Published → บรรทัด Output เป็นสีเขียว
- [ ] **ลบเอกสารตัวสุดท้ายในกระบวนการ (draft) → เฉดพื้นหายกลับเป็นพื้นเดิม** (auto)

## 8.1 ลบเอกสารร่าง (ป้องกัน upload ผิดไฟล์)
- [ ] เอกสารสถานะ **ร่าง** (ยังไม่เคยเผยแพร่) → ผู้จัดทำ/admin เห็นปุ่ม **🗑 ลบ**
- [ ] กดลบ → ยืนยัน → เอกสารหายจากรายการ · ไฟล์ถูกย้ายไปถังขยะ Drive (กู้คืนได้)
- [ ] เอกสาร review/approved/published หรือ draft-ระหว่าง-revision (มี effective) → **ไม่มีปุ่มลบ** (กัน controlled document หาย)

## 9. PWA / มือถือ
- [ ] เปิดบนมือถือ → layout ใช้ได้ (การ์ด/ตารางเลื่อนได้ ไม่ล้นจอ)
- [ ] (production/HTTPS) เบราว์เซอร์ขึ้นให้ "ติดตั้งแอป" / Add to Home Screen
- [ ] ติดตั้งแล้วเปิดเป็นแอป (standalone) มีไอคอนโล่ navy-jade

## 10. Feature A — Version control (check-out/check-in)
- [ ] เอกสาร **เผยแพร่** → ผู้จัดทำ/admin เห็นปุ่ม **เช็คเอาต์แก้ไข** → กดแล้วขึ้น 🔒 "กำลังแก้โดย ..."
- [ ] คนอื่น (ไม่ใช่ผู้ถือ) เห็นล็อก แก้ไม่ได้
- [ ] **เช็คอินเวอร์ชันใหม่** → เลือก *แก้ไขย่อย* → ได้ **v1.1 (ร่าง)** · เลือก *แก้ไขใหญ่* → ได้ **v2.0**
- [ ] ระหว่างรุ่นใหม่ยังไม่เผยแพร่ → กด **⬇︎ PDF** ได้ **เวอร์ชันเดิม (effective)**
- [ ] รุ่นใหม่เดิน workflow จนเผยแพร่ → กลายเป็น effective (เลขเวอร์ชันอัปเดต) · เวอร์ชันเดิมเป็นประวัติ
- [ ] **ยกเลิกเช็คเอาต์** → ปลดล็อก สถานะคงเดิม
- [ ] หน้า `/documents/[id]` → ประวัติเวอร์ชัน (label + timestamp) + Timeline ครบ

## 11. Feature B — ปฏิทิน ISO + แจ้งเตือนล่วงหน้า
- [ ] `/calendar` แสดง 31 รายการ + งวดกำหนดการตามวงรอบ (เดือน/ไตรมาส/6 เดือน/ปี)
- [ ] สีงวดถูกต้อง (เขียว=เสร็จ · แดง=เลยกำหนด · ส้ม=ใกล้ ≤14 วัน · ฟ้า=อนาคต)
- [ ] admin ปรับ **แจ้งล่วงหน้า X วัน** ต่อรายการ → กดบันทึก → ค่าเปลี่ยน
- [ ] admin กดงวด → สลับสถานะ เสร็จ/ค้าง ได้
- [ ] admin กด **▶ ส่งแจ้งเตือนที่ถึงกำหนดตอนนี้** → 🔔 ขึ้นเลข + (ถ้าตั้ง Resend) ได้อีเมล
- [ ] แจ้งเตือนยิงเฉพาะงวดในช่วง [กำหนด − lead_days, กำหนด] · กดซ้ำไม่ยิงซ้ำ (idempotent)
- [ ] (production) Vercel Cron ยิง `/api/cron/reminders` รายวันอัตโนมัติ
- [ ] **Import ปฏิทิน** (admin): ปุ่มบน AppBar → แนบ .pdf + เลือกปี → นำเข้าสำเร็จ → `/calendar` สลับปีได้ (year selector)
- [ ] Import ปีที่มีอยู่แล้ว → ขึ้นเตือน "มีอยู่แล้ว" + ต้องกด "ทับของเดิม" จึงแทนที่ (กันซ้ำ)

## 12. Regression อัตโนมัติ
- [ ] `npm run test` → ผ่านทั้งหมด (policy: สิทธิ์ดาวน์โหลด + workflow actions)
- [ ] `npm run build` → ผ่าน ไม่มี error
